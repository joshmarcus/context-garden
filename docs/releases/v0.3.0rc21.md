# Context Garden 0.3.0rc21

This prerelease fixes branch-cleanup reference matching that could hold the scheduler loop for minutes as run history grew. Cleanup now builds a fresh reference index for each state snapshot and checks only the relevant recovery IDs during a single-branch deletion recheck. Exact run-ID boundaries, suffixed siblings, nested recovery paths, active/base ownership and fresh compare-and-delete guards remain intact.

A generated13MiB/5,000-ID benchmark measured21.771449seconds with the previous matcher and2.335829seconds with the new index. A separate read-only Windows-through-WSL check processed a12.85MB operational snapshot in0.923seconds and agreed with an independent oracle for all4,984 IDs. These measurements cover matching; whole-scheduler and page latency require separate observation. RC20's original slow passes and recovery interventions remain preserved in the operational account.

Other included changes:

- Collection continuations wait for durable Run finalization when a newer worker completion wins a concurrent save, preserving ownership and preventing stale advancement.
- Browser validation follows explicit policy instead of running Playwright work by default.
- Live task/run output retains complete entries in scrollable panels and preserves reading position during polling.
- Validation fixtures isolate their deliberate failure cases from unrelated inherited pytest options.
