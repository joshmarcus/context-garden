# v0.3.0rc12 durable worker-question handoff

This candidate starts from exact published v0.3.0rc11 and adds only the reviewed
worker-question publication correction and its deterministic regression. When a
worker asks for input, the controller now persists the question and its complete
resume identity before the task becomes visible as waiting for a person. An
immediate answer from another process therefore resumes the session that asked the
question instead of observing an incomplete side-state and starting a fresh run.

The regression reads state through a separate `State` instance at the exact task
status publication boundary. It verifies the question, session id, session host,
session harness, and originating run together. Existing v0.3.0rc11 decision and
review-feedback persistence, clean-head merge approval lineage, conflict checks,
atomic merge-head guards, and quiet optional-evidence handling remain unchanged.

There is no storage migration, state reset, credential rotation, host launch,
resource-limit change, transport change, or worker wire-protocol change. Existing
v0.3.0rc10 workers remain compatible with a controller-first deployment. The known
worker transport limitation remains, so active generations and results must still
be accounted and reconciled around deployment.

Bounded decision, QA, and canary tests, the focused question path, Ruff, source-diff
review, independent exact-source review, and exact-head full CI are required before
publication. Publication and deployment remain separate gated steps.
