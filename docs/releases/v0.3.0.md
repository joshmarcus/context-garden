# Context Garden 0.3.0

Context Garden 0.3.0 is the stable release following the completed Phase05 closing review and its recorded acceptance with limitations. It builds on the RC21 line and accepted main `62f31c843c224ff86b44190f17f7227601cdec94`. Phase closure is a recorded operational disposition, not a claim that every historical target passed.

The release includes persistent worker presence, authenticated work claims and completion, recovery provenance, finite host lifecycle controls, per-product verification settings, and the reviewed scheduler/UI and cleanup improvements developed through the release candidates. Existing worker claims, final results, source identities and operator decisions retain their provenance.

Changes accepted since RC21:

- Per-product check commands, analysis and timeouts stay attached to the dispatched verification contract, including continuation and base-probe paths. Required checks remain distinct from CI analysis.
- Explicit, attributable stabilization acceptance is bound to one phase and build. It records accepted limitations separately from measured PASS/FAIL/UNPROVEN evidence and preserves unfinished-task, owner-question and ordinary closure gates. Changed acceptance content invalidates a previously prepared closing review.
- Obsolete discovery and duplicated brief helpers are removed while preserving retained behavior and compatibility.
- Ontology and design references are consolidated against the accepted implementation, with original persona provenance retained.

The native Phase05 closure occurred on September 11, 2026 after the accepted CG537 final account and CG623 repair. All 24 original review reports, failures, recovered-source identities, unknown costs and intervention records remain unchanged. First-pass approval, outside-queue merge-mechanism and agent-rebase targets were missed; complete easy-task economics and operator share remain unproven. Those outcomes were accepted by the delegated operator under the owner's all-human-actions instruction, with the existing accountable follow-through.

Current planner isolation remains opt-in. The observed configuration does not establish enforced workload isolation or authorize untrusted workloads. The accepted account records ordinary controller ticks of 15.341–18.287seconds against a 10-second warning; this release makes no universal latency promise. Live-cloud canaries are optional and are not claimed as performed by release validation. macOS deployment is untested; Linux and Windows-through-WSL observations must be reported only where actually exercised.

Source acceptance, release publication and installation have separate evidence. Publication requires actual merged-main and exact-candidate CI, applicable deterministic/protocol checks, artifact/source identity verification and independent release/rollout review. Production activation preserves active work, rollback, current caps and finite host authority; a version change grants no additional hosts, spending or deadline extension.
