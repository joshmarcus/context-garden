# v0.3.0rc13 worker recovery and truthful run lifecycle

This release starts from main commit 10753d74f4376b54c9a6d2c95f11f9a4233ef86e, whose full CI passed, and integrates the reviewed setup, worker recovery, completed-run collection, harness-pause and lifecycle presentation corrections.

Workers report checkout preparation failures through authenticated, bounded recovery. Dirty or conflicted checkouts and setup markers are preserved before a new generation prepares clean source. Checkout ownership follows the supervised process so recovery cannot move a surviving author's files. The merged transport retry and queue-time accounting changes are included.

Fresh base probes get a setup cache identity for their actual checkout lifetime. A failed setup remains an unavailable check with its original exit details and bounded retries, rather than being reported as proof that main is broken. A stale read of the harness-pause map cannot overwrite a newer pause.

Accepted remote results left behind when a task becomes terminal are collected without reopening the task or replaying source publication. Board and Now distinguish queued work, recorded remote claims, manual reservations and results awaiting collection; recorded claims do not assert worker-process liveness. Capacity uses scheduler accounting.

The main base also includes the merged PR board, origin-aware task navigation, local investigation reports, repo-wide PR observation and quiet build detail. Earlier durable question, decision and review-feedback handling and clean-head atomic merge policy remain required release behavior. The release also restores the recipient configuration fence, deferred author evidence, null observation handling and derived-head approval audit from previous validated releases; CG489 tracks these corrections for main-source integration.

Controller and workers require the new version to provide the complete recovery behavior. Deploy through accounted controller replacement and guarded worker idle boundaries, retaining original run/source/result records and rollback runtimes. Existing host identities, absolute shutdown deadlines, budget, admission limits and explicit task/phase holds are preserved. Transport lease duration is restored only after actual recovery verification.

Publication requires exact-source full CI, proportionate backend and rendered-page regressions, independent review and the actual served TCP journey. Deployment and live verification follow publication; this document alone is not a deployment receipt.
