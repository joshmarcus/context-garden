# context-garden 0.4.3

This release ships current main after completion of Phase 10, bringing together
the multiplayer, ownership and interface improvements with the existing PR-review
and workflow fixes.

- Git-backed coordination in the Garden repository replaces the separate shared
  coordinator design. Local servers synchronize accepted ownership and protect
  task execution and handoffs through the existing permission and work guards.
- Configured, admitted users open their local session at server startup, including
  the temporary OS-username mode. Personal Inbox views and available actions follow
  that identity without another routine browser login or connect step.
- Tasks inherit their accepted phase owner unless explicitly assigned or unassigned.
  Ownership changes use guarded handoffs while preserving source and execution history.
- Project selection moves into the left sidebar below Phases, with compact mobile
  navigation and project scope preserved through normal and live navigation.
- Operating profiles use Default, Economy and Fast. Economy/Fast scale worker and
  review concurrency while preserving configured models and resource caps.
- Task pages expose Mark done for externally completed work and prioritize useful
  content over secondary controls. Attention counts track actionable decisions.
- PR review accepts substantive alternative evidence and justified criterion
  amendments, while retaining material review and CI gates.

Multiplayer remains opt-in with `multiplayer.enabled`; configure the documented
Git coordination and membership requirements before enabling it. Browser credentials
do not change the server's installation-bound execution principal. See the included
multiplayer and configuration documentation for migration and deployment procedures.

Python 3.11 or later is required; Windows operation remains through WSL. Install
with `python -m pip install --upgrade context-garden==0.4.3` in the intended environment.
To return to the prior stable package, use `context-garden==0.4.2` through the normal
maintenance procedure and preserve task/run history. Publication itself does not
upgrade or restart existing controllers or workers.
