# v0.3.0rc10 serial merge safety and review signal quality

This candidate starts from exact published v0.3.0rc9 and adds only the approved
CG-464 and CG-465 source changes. Clean reviewed pull-request heads can merge
without a redundant rebase when the repository explicitly opts out, while an
atomic expected-head guard prevents merging a head that changed after its final
check. The default remains to rebase before merge.

Automated reviews omit nits and caveats caused only by unattached artifacts or
missing optional evidence metadata. Operator diagnostics remain available separately,
while real defects and contradictory source claims still block.

There is no storage migration, state reset, credential rotation, host launch,
concurrency change, or worker protocol change. Exact-candidate focused tests,
independent review, exact-head full CI, and the required TCP application journey
remain release gates. Tagging, publication, and deployment require a separate
explicit gated step. Existing Phase05 holds remain in force.

After a necessary mechanical rebase, the clean-head policy preserves approval only
through a durable chain that starts at the original approved commit and proves
unchanged patch identity at every step. An unproven chain requests one fresh
exact-head review. The original approving review remains unchanged. A push lease
bound to the pre-rebase remote head rejects concurrent author changes.
