# v0.3.0rc16

RC16 makes live Now-page event refreshes share one coherent, short-lived snapshot instead of rebuilding the complete page state independently for every region. Partial responses no longer compute the unrelated global navigation and Inbox context, and concurrent run-strip refreshes share their historical duration baseline. The initial page, live run lookup, event-driven freshness, templates, progress clocks, actions, and request protections remain unchanged.

A change signature over the event log and scheduler state is sampled while holding the refresh mutex. A later event or state write therefore forces a new snapshot even when it arrives while an earlier snapshot is still building; different reporting windows remain isolated. Snapshot construction also reuses one run-history materialization for task spend and in-flight strips.

This is a controller-only release. Existing RC13 workers remain protocol-compatible and do not require a fleet rollout. RC16 includes RC15's bounded idle-worker claim scan and all RC14 and RC13 safeguards.
