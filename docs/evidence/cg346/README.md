# Live managed EC2 canary

The real EC2 host completed work, a check, and review through the portable HTTPS protocol. An additional host-side check verified unprivileged execution (UID 999), blocked IMDS access, disk-backed temp, and refusal to acquire a second host lock. After a synthetic harness streamed a progress marker, the instance was terminated. Nineteen returned artifacts survived, the expired run could be reclaimed over HTTPS, and the prior lease was rejected with HTTP 409. AWS then reported zero remaining trial volumes and network interfaces.

See `live-canary.json` for actual host/version/resource attribution, repairs, limits, and cost estimates; `http-events.json` contains observed HTTP status codes. The model harness and GitHub API were deterministic fakes. This is real cloud transport/execution evidence, not evidence of real model authentication, reviewer quality, or production deployment.

The worker ran source `3e2f3699e88732c05a3ed62b89ed9211cd4cf41c`. A restrictive bootstrap umask initially blocked the service from traversing its installed runtime. The same host was repaired without launching a second instance; the PR includes the permission fix and persistent firewall startup ordering. An initial repair boot also exposed a synchronous boot-hook restart deadlock. The recovery hook used `systemctl --no-block`. A clean-image replay of the final bootstrap remains unproven.

The disposable controller and Git service were separate processes: hosting a Git remote in the same asynchronous application deadlocked a synchronous self-fetch during claim. Production Garden stayed on its prior installed build. After the trial, both temporary Serve routes and services were removed, the bootstrap secret's current value was retired, and generated local enrollment payloads were deleted. The consumed owner-supplied Tailscale key was retained in its original private location. The bootstrap secret resource remains billable; the aggregate allocation remains $80.
